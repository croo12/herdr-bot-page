# 봇과 채팅을 분리하고 봇이 자신에게 온 메시지를 찾게 한다

봇 A가 “내게 새로 온 메시지가 있는가?”를 한 번 조회하면, 사용자가 A에게 보낸 메시지와 봇 B가 A에게 보낸 메시지를 각각의 1:1 대화에서 찾을 수 있어야 한다. 사용자가 대화를 열었는지, A가 메시지 도착 순간에 실행 중이었는지와 무관하게 동작해야 한다. [용어 정의](../../CONTEXT.md)

## 변경 전의 한계

기존 개별 대화는 채팅 ID를 그대로 봇 ID로 사용했다. 봇 간 위임도 대상 채팅에 메시지를 저장한 뒤 그 채팅의 메모리 큐에 작업을 넣었다. 다른 채팅에서 일하던 봇은 실행 순서에서 건너뛸 수 있었고, 재시작한 봇이 자신에게 남은 메시지를 찾을 방법이 없었다.

## 참여자와 대화

- 봇은 프로필, 제공자, 작업 디렉터리, 권한 설정과 실행 세션을 소유한다. 채팅은 독립된 ID, 참여자, 메시지 기록을 소유한다. 메시지를 보낼 때 발신자와 목적지 채팅을 각각 지정한다.
- 1:1 대화는 사용자–봇 또는 봇–봇 조합으로 연다. 두 참여자가 동시에 열거나 순서를 바꿔 열어도 같은 채팅 ID를 반환한다. 그룹에서 멤버가 나가 두 명만 남아도 그룹 ID와 이력은 유지한다.
- 화면에서 봇을 선택하면 프로필이 열리고, ‘1:1 대화’로 그 봇과 나의 채팅을 연다. 내 채팅 목록에는 내가 참여한 대화가 표시된다. 사용자가 채팅을 읽어도 봇의 수신 상태는 바뀌지 않는다.

## 새 메시지의 수신과 처리

| 메시지가 쓰인 곳 | 수신함에 들어가는 봇 |
| --- | --- |
| 사용자와 A의 1:1에서 사용자가 발신 | A |
| A와 B의 1:1에서 A가 발신 | B |
| 그룹에서 특정 봇에게 멘션 또는 명시적으로 위임 | 수신자로 지정한 현재 멤버. 중복 지정은 한 번으로 계산한다. |
| 그룹에서 사용자가 수신자 없이 발신 | 기존 그룹 대화처럼 현재 멤버 봇들이 대화에 참여할 수 있도록 각 봇에 전달한다. |
| 그룹에서 봇이 다른 봇의 메시지에 답글을 작성 | 현재 멤버인 원작성자와 명시적으로 멘션한 봇에 각각 한 번 전달한다. |
| 그룹에서 봇이 답글 대상이나 멘션 없이 발신하거나 시스템이 상태를 알림 | 대화 기록에만 남긴다. |

발신 봇은 수신자에서 제외한다. 메시지와 수신자별 항목을 같은 트랜잭션에 저장하고, 메시지 ID와 수신 봇 ID의 조합을 유일하게 유지한다. 멤버가 나가면 해당 채팅의 미처리 항목을 닫고, 새 멤버에게 가입 전 메시지를 소급 전달하지 않는다.

봇은 활성 대화 턴이 없어도 자신의 수신함을 조회할 수 있다. 호스트는 호출한 세션으로 봇 신원을 확인한다. 조회 결과에는 채팅 ID, 메시지 ID, 발신자가 포함되며, 조회만으로 처리 완료되지 않는다. 답장은 원래 채팅에서 작성한다.

실행 중에는 새 메시지 이벤트가 수신함 확인을 깨운다. 시작·재연결 시, 그리고 다른 턴을 끝내고 유휴 상태가 됐을 때도 저장된 미처리 항목을 조회한다. 동시에 두 워커가 같은 항목을 가져가도 한 워커만 처리권을 얻는다. 답장 저장 또는 명시적 건너뛰기와 수신 완료를 한 트랜잭션으로 확정한다. 중단된 처리권은 회수하며, 이미 확정한 답장은 재전달 시 다시 게시하지 않는다. 외부 명령의 실행 여부가 불명확하면 재실행 전에 결과를 확인한다.

## 승인 요청과의 관계

검토 봇이 받는 메시지는 원래 승인 요청 ID를 참조한다. 결정 제출은 그 요청에 대한 별도 동작으로 제공한다. 호스트는 배정된 검토 봇, 요청의 대기 상태, 현재 터미널 프롬프트가 일치할 때만 결정을 적용해 원래 채팅의 승인 카드를 갱신한다. 사용자가 먼저 응답하면 늦은 검토 답변은 결정에 영향을 주지 않는다. [현재 검토 검증](../../native/src/modules/reviews/service.rs)

1:1 대화와 수신함은 검토 메시지가 누구에게 갔는지 해결한다. 검토 답장 명령이 다시 사용자 승인을 요구하는 문제는 별도로 다룬다. 결정 제출 경로의 권한 범위를 검토할 때 강제 push처럼 사용자의 명시적 승인이 필요한 작업은 사람에게 보낸다.

## 적용 순서와 검증

1. **ID와 저장 모델을 분리한다.** 기존 그룹의 ID와 메시지 참조를 보존한다. 이전 CLI의 봇 ID 목적지는 발신자와 봇의 조합으로 1:1 채팅을 찾도록 연결한다. 기존 개별 기록은 참여자를 확정할 수 있는 메시지만 해당 1:1로 연결한다. 답장·작업·승인 참조를 함께 보존할 수 없거나 참여자가 모호한 기록은 원래 이력에서 조회할 수 있게 둔다. 이전을 재시도해도 복제되지 않아야 한다.
2. **1:1 대화와 수신함 조회를 연다.** 전환 이후 발신한 메시지부터 수신 항목을 기록한다. 과거 이력을 새 요청으로 일괄 발행하지 않는다. 한 사용자와 두 봇으로 세 쌍의 1:1 대화를 만들고, 각 대화의 기록과 수신자가 분리되는지 확인한다.
3. **수신함을 턴 실행에 연결한다.** 기존 채팅 큐와 수신함 워커가 한 메시지의 응답을 동시에 시작하지 않도록 실행 주체를 전환한다. A가 다른 그룹에서 일하는 중에 도착한 DM, 이벤트 유실 직후 재시작, 답장 확정 직후 재시작을 각각 검증한다. 세 경우 모두 원래 채팅에 답장이 한 번만 남아야 한다.
4. **승인 검토를 연결한다.** 검토 봇에게 요청이 한 번 도착하는지, 원래 승인 카드에 결과가 반영되는지, 사용자와 봇이 동시에 답해도 결정이 한 번만 적용되는지 확인한다.
